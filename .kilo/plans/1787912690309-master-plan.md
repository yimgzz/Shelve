> Single source of truth for architecture, data model, interfaces, and build strategy.
> Every phase plan links back to the sections (§) that must be read before implementation.
> Status: v1.1 (2026-08-29). App UI language: English only.
>
> **History**
> - v1.1 (2026-08-29): Phases 3–5 decomposed into sub-phases (3a–3e, 4a–4d, 5a–5c) sized for ~190k-token agent contexts. Packaging/flatpak phase (former Phase 6) **cancelled and removed** from the roadmap.

## §1 Goals & Non-Goals

**Goals**
- Lightweight, fast, fully local SSH session manager (no cloud, no telemetry, no accounts).
- Go backend (`golang.org/x/crypto/ssh`) + Wails v3 frontend (vanilla TypeScript + Vite + xterm.js), no Electron.
- Encrypted vault (AES-256-GCM, key from Argon2id(master password)); zero plaintext credentials on disk.
- Hierarchical tree (folders → subfolders → sessions) with live search, comfortable with 200+ sessions.
- Session card: Name, Host, Port, User, auth (password **or** SSH key path), structured Jump Hosts, "Extra Args" (limited, validated subset).
- Terminal tabs above the terminal pane; session tree + search on the left; terminal on the right.
- Optional SFTP browser (settings checkbox) that replaces the tree when a session is active; browse, upload/download, basic ops, edit text files with the system editor.
- Dark & light themes (system-aware), UI/UX best practices.
- Developed and built entirely in Docker (no local deps on the developer's ALT Linux desktop).
- Cross-distro delivery via `wails3 package` (AppImage primary, DEB, RPM) — available ad-hoc via Phase 1 Makefile targets. The dedicated packaging/release phase was **cancelled (2026-08-29)**: packaging is NOT part of the v1 roadmap or acceptance criteria. Flatpak: out of scope.

**Non-goals (v1)**
- Windows/macOS *distribution* (build targets exist in Makefile; no signing).
- Session sharing/sync, multi-window, session recording/audit, auto-reconnect (manual Reconnect button only).
- Drag-and-drop in the session tree (context-menu "Move to…" instead).
- E2E UI test framework (manual QA checklists per phase; `tsc` + eslint for frontend).
- Russian/other UI languages (English only).

## §2 Resolved Decisions

| # | Decision | Choice |
|---|----------|--------|
| D1 | Distribution | Docker-built binary (`make build`) is the v1 delivery path. AppImage/DEB/RPM remain available ad-hoc via `wails3 package GOOS=linux`. Flatpak: out of scope (packaging phase cancelled 2026-08-29). |
| D2 | Frontend | Vanilla TypeScript + Vite (default Wails v3 template). No framework. xterm.js from npm. |
| D3 | Vault unlock UX | Master password prompted on every start. Key lives in memory only. Explicit Lock button. Opt-in auto-lock after N min inactivity (default 0 = off). Master password is never written to disk; per-file random salt + Argon2id. |
| D4 | SFTP scope | Browse, upload, download, mkdir, rename, delete — reuses the active session's SSH connection — **plus** "edit text file with system editor" (download to temp → launch configured external editor → detect save → re-upload). |
| D5 | Jump hosts / Extra Args | Jump hosts are first-class structured fields (ordered list; each: host, port, user, password or key path). Extra Args is a free-form string parsed by a strict parser: `-L`/`-D` local port forwards, curated `-o` subset, `ProxyJump=` shorthand. Unknown flags → validation error at save time. |

**Additional architect decisions (defaults, changeable by owner)**
- A1 Host keys: OpenSSH `known_hosts` file managed by the app (TOFU: prompt to accept a new key; reject on mismatch; never auto-accept).
- A2 SSH key file passphrases are never stored; prompted once per connection, cached in process memory for the app session.
- A3 Tabs are ephemeral: closing the app closes all sessions; no tab restoration on relaunch.
- A4 No auto-reconnect. On disconnect the tab shows an error overlay with [Retry] / [Close].
- A5 Large file data never crosses IPC: uploads/downloads pass *paths*, Go streams the bytes (sftp). Only terminal I/O and events cross the Wails IPC.
- A6 Terminal output is batched in Go before emitting events (≤50 ms or ≤16 KB per emit).
- A7 One app window (single-window app); window geometry remembered in settings.json.
- A8 Destructive tree ops (delete folder with children, delete session) require a confirm dialog showing the affected count.
- A9 Search matches Name, Host, User (case-insensitive substring); folder path shown in results for context.
- A10 Session ID: ULID; folders and sessions keep explicit sibling order (array positions), move = re-index.

## §4 Data Model & Storage

All data under XDG config dir: `$XDG_CONFIG_HOME/shelve` (fallback `~/.config/shelve`), created 0700, files 0600. Never write outside this dir.

| File | Content | Encrypted? |
|---|---|---|
| `vault.json` | Envelope: `{"v":1,"kdf":{"alg":"argon2id","salt":"<b64>","time":3,"memory":65536,"threads":4},"enc":{"alg":"aes-256-gcm","nonce":"<b64>"}}` + binary ciphertext of the JSON payload (AAD = string `"dsmsv1"`). Payload = `{"folders":[...],"sessions":[...]}` | YES |
| `settings.json` | No secrets. See below | no |
| `known_hosts` | OpenSSH known_hosts subset: `host ssh-ed25519 AAAA...` / `host ssh-rsa AAAA...`, `[host]:port` supported, hashed/wildcard entries read-only (skipped on write-back) | no (host keys are not secret) |
| `tmp/` | SFTP edit temp files (created 0600, removed on lock/exit) | — |

**settings.json schema**
```json
{
  "theme": "system | light | dark",
  "autoLockMinutes": 0,
  "sftpBrowserEnabled": false,
  "terminal": { "fontFamily": "monospace", "fontSize": 13, "scrollback": 10000 },
  "textEditorCommand": "xdg-open",
  "window": { "width": 1280, "height": 800 }
}
```

**Model (Go, `internal/model`)**
```go
type Folder struct { ID, ParentID string; Name string; Children []string /*IDs*/ }
type AuthType int // AuthPassword | AuthKey
type Auth struct { Type AuthType; Password string; KeyPath string }
type JumpHost struct { Host string; Port int; User string; Auth Auth }
type Session struct {
    ID string; FolderID string
    Name string; Host string; Port int; User string
    Auth Auth; JumpHosts []JumpHost; ExtraArgs string
}
```
- Key file passphrase: NOT in the model (A2).
- Validation rules: Name non-empty; Host hostname/IPv4/IPv6; Port 1–65535; User non-empty; exactly one auth method filled (password XOR key path); jump host ports/users validated; ExtraArgs must pass the §5 parser; duplicate names within one folder allowed (no uniqueness constraint).
- Concurrency: single `Store` with `sync.RWMutex`; every mutation re-encrypts & atomically writes `vault.json` (temp file + rename), debounced 300 ms; flush on `Lock` and app exit.

## §5 Architecture

### Package layout
```

internal/
  app/        # composition root: wires config+store+vault+engine; master-password lifecycle; locks close all sessions
  config/     # XDG paths, settings.json load/save
  model/      # types + validation (§4)
  store/      # in-memory tree CRUD, order ops, move/delete semantics, persistence trigger
  vault/      # argon2id KDF, AES-256-GCM envelope, first-run create, unlock, lock, zeroization
  sshx/       # args parser (§2 D5), known_hosts manager, host-key callback factory, auth method builders
  sshengine/  # SessionManager: dial (jump chain), pty session, event emitter (batched), window change,
              # local port forwards, close/reconnect, key-passphrase prompt flow
  sftp/       # sftp ops on an active connection: list/mkdir/rename/remove/get/put, temp-file editor flow
  wailsvc/    # Wails services (the ONLY package that imports wails): AppService, VaultService,
              # SettingsService, SessionService, TerminalService, SftpService
frontend/
  index.html
  src/
    main.ts       # bootstrap, event bus subscription, unlock gate
    store.ts      # tiny pub/sub state (tree, tabs, settings, search)
    components/   # tree.ts, tabs.ts, session-editor.ts, settings-dialog.ts, sftp-panel.ts,
                  # unlock.ts, toasts.ts, confirm.ts
    terminal/     # xterm wrapper (init, resize, data pump, error overlay)
    ui/           # dom helpers, theme.ts (CSS vars, system dark listener), shortcuts.ts, dialog.ts
    style/        # base.css, themes.css (custom properties), components.css
    bindings/     # generated by wails — never edited, gitignored
build/            # wails build config, appicon.png, linux packaging metadata
Taskfile.yml      # wails-generated tasks
Makefile          # our docker-driven targets (§7)
Dockerfile.dev    # shelve-dev image
docker/sshD/      # integration-test sshd image (docker/sshD/Dockerfile)
```

### Wails services (JS → Go, all async Promises in JS)
- `VaultService`: `Status() -> unlocked bool`, `CreateVault(pw)`, `Unlock(pw)`, `Lock()`, `ApproveHostKey(connID)`, `RejectHostKey(connID)`, `SubmitKeyPassphrase(connID, pw)`.
- `SessionService`: `Tree() -> [NodeDTO]`, `CreateFolder(parentID, name)`, `RenameFolder(id, name)`, `MoveNode(id, newParentID, index)`, `DeleteNode(id) -> {deletedCount}`, `CreateSession(dto)`, `UpdateSession(dto)`, `DuplicateSession(id)`, `ValidateExtraArgs(s) -> error?`, `TestConnection(sessionID or draft DTO)`.
- `TerminalService`: `Connect(sessionID) -> tabID`, `Disconnect(tabID)`, `Write(tabID, dataB64)`, `Resize(tabID, cols, rows)`, `Reconnect(tabID)`.
- `SftpService`: `IsActive(tabID)`, `List(tabID, path) -> [Entry]`, `Cd(tabID, path)`, `Mkdir/Rename/Remove(tabID, ...)` , `PickLocalFiles(tabID, multi) -> [paths]`, `Upload(tabID, localPaths, remoteDir)`, `Download(tabID, remotePath) -> localTempPath`, `DownloadThenSave(tabID, remotePath) -> finalPath` (Go save-dialog), `EditRemoteText(tabID, remotePath)`, `TransferProgress events only (Go→JS)`.
- `AppService`: `GetSettings()`, `SaveSettings(s)`, `GetVersion()`.
- DTOs in `internal/wailsvc/dto.go` — JSON-friendly, never expose internal structs (secrets never leave the vault in Tree(): passwords/keys omitted, `HasPassword`/`AuthType` exposed instead).

### Event contract (Go → JS, via `app.Event.Emit`; JS subscribes with `Events.On`)
Wait for `events.Common.WindowRuntimeReady` before emitting anything UI-facing.

| Event | Payload | Producer |
|---|---|---|
| `vault:state-changed` | `{unlocked: bool}` | vault/app lifecycle; frontend swaps unlock screen |
| `vault:hostkey-prompt` | `{connID, host, port, keyType, keyB64, fingerprint}` | sshx host-key cb on unknown host; **modal** with [Accept and connect] / [Reject] |
| `vault:key-prompt` | `{connID, keyPath}` | encrypted private key hit; modal single password input |
| `terminal:status` | `{tabID, state: "connecting"|"ready"|"error"|"closed", message?}` | sshengine |
| `terminal:data` | `{tabID, data b64}` (batched ≤50 ms / ≤16 KB, §2 A6) | sshengine |
| `terminal:exit` | `{tabID, exitStatus?}` | remote shell exited |
| `ssh:forward` | `{tabID, spec, state: "listening"|"closed"|"failed", localAddr?, error?}` | sshengine |
| `sftp:progress` | `{transferID, direction, doneBytes, totalBytes}` | sftp |
| `app:toast` | `{level: "info"|"error", message}` | services (validation/network errors not bound to a call site) |

### Threading / failure modes
- One goroutine per open SSH connection (read pump, forward accepts); all store access via mutex; emitter buffers per tab.
- `Lock()` while sessions open: disconnect all, zeroize key, emit `vault:state-changed`.
- Disconnect while active: state `error` + message, tab kept (A4); Reconnect re-runs the full dial.
- Port-forward bind failure: non-fatal — `ssh:forward failed` + toast; connection proceeds.
- Corrupt/decryption-failed `vault.json`: app refuses to unlock, shows guidance (app never auto-overwrites a vault it cannot decrypt; document backup/restore in README).
- Backpressure: if pending terminal buffer for a tab > 1 MiB, pause the SSH read loop (TCP window applies remote-throttling) until drained.

## §8 Security Requirements (binding)
1. No plaintext credentials anywhere on disk. `vault.json` is the only store of secrets; `settings.json` and `known_hosts` are audited to contain none (gated by unit test asserting key fields absent from plaintext).
2. Argon2id params: m=64 MiB, t=3, p=4; 16 B random salt; 32 B key; AES-256-GCM with random 12 B nonce per write; AAD `"dsmsv1"`.
3. Memory hygiene: master password and derived key zeroized after use; keys never logged. Error messages never include passwords/key material (asserted by tests).
4. File/dir perms: config dir 0700, files 0600 (asserted by test).
5. Host keys: TOFU via app-managed `known_hosts` (§2 A1); mismatch = hard fail with clear error.
6. SSH key files: read-only use; app never writes or rewrites user key files.
7. Vault writes are always atomic (tmp+rename) and never truncated on failure.
8. Temp SFTP edit files 0600 in `tmp/`, swept on lock/exit/app-crash (best effort on next start).
9. No network calls except to user-specified SSH hosts and local port-forward sockets (127.0.0.1). No telemetry, no updates check, no crash reporting.

## §9 Testing Strategy
- **Go unit** (in docker, `make test`, run with `-race`): vault round-trip / wrong-password / tamper; args parser (all supported flags, all rejection cases); known_hosts parse/write; store CRUD/move/delete/ordering; model validation; settings load/save; perms & no-secret-leak assertions (§8).
- **Go integration** (`make test-integration`, tag `integration`): testcontainers-go spinning sshd images from `Dockerfile` `docker/sshd` (openssh-server, known user+password and key pairs baked in). Cases: password auth; key auth (incl. passphrase prompt path via engine API); PTY echo (`echo hi` → expect output); jump chain (container A → container B → target); local forward (`-L` on 127.0.0.1, dial-through works); host-key mismatch rejection; disconnect → `terminal:exit`/`status` event correctness; store fixture with 300 sessions for perf smoke (search < 10 ms, tree ops < 50 ms wall).
- **Frontend**: `tsc --noEmit` + `eslint` in CI-like `make lint`; manual QA checklist per phase (checklist embedded in each phase plan). No e2e framework in v1.
- **Perf smoke**: scripted 300-session vault; search timing log; 100 KB/s terminal feed (remote `yes | head -c 1000000`) with FPS sanity check (manual).

## §11 Risks & Mitigations
| Risk | Mitigation |
|---|---|
| Wails v3 is **beta** — API churn | Pin exact version; isolate ALL wails imports in `main.go` + `internal/wailsvc`; prefer the small stable subset (options, services, events, dialogs, window state); avoid bleeding-edge features (multi-window, hooks) in v1. |
| WebKitGTK 6.0 availability on target distros | Build once in container; AppImage bundles the runtime so end users need zero deps; legacy `-tags gtk3` fallback documented for older distros. |
| `github.com/pkg/sftp` maintenance mode | Pin version; API is stable and small; swap-behind-`internal/sftp` if archived. |
| High-throughput terminal output saturating IPC | Batching (§2 A6) + 1 MiB backpressure pause; webgl renderer; measure in Phase 4c perf smoke. |
| NVIDIA/gbm blank window on some desktops | Wails auto-sets `WEBKIT_DISABLE_DMABUF_RENDERER=1`; re-document manual env fallback in README troubleshooting. |
| Docker dev on Wayland | X11 forwarding via XWayland; document; native Wayland support = non-goal v1. |
| Corrupted vault brick | Atomic writes; app never overwrites a vault it cannot decrypt; README: keep `vault.json` backups; manual recovery = re-create. |
| x/crypto/ssh lacks known_hosts/agent features | Own minimal implementation in `sshx` (A1); agent support explicitly out of scope v1 (key file + passphrase only). |

## §12 Global Acceptance Criteria (definition of done for the project)
1. Built binary (`make build`) runs on a stock recent Linux desktop (tested on Debian 13 container + host machine) with zero installed dependencies; window opens < 2 s. (Distributed packaging deferred — ad-hoc `make package` only, per the cancelled Phase 6.)
2. 300-session vault: unlock < 1 s (after Argon2id KDF ≤ ~500 ms), live search responsive, tree operations snappy.
3. All §8 security invariants hold (tests green, `-race` clean).
4. End-to-end: create folder → create session (password & key variants, jump host) → connect → terminal works → SFTP browse/upload/download/edit text file → lock → app unusable without password.
5. `make build`, `make test`, `make lint` all pass from a clean container with no host-side toolchain (`make package` excluded — packaging phase cancelled).
6. README: overview, build & run (Docker-only dev workflow), first run & master password, security model, session card reference (incl. Extra Args grammar), shortcuts, SFTP usage, troubleshooting. (Installer-style docs for AppImage/DEB/RPM/Flatpak deferred with the cancelled packaging phase.)
