# Phase 3 — SSH Engine (dial, jump chains, PTY, forwards, prompts, args parser)

**Type:** Backend. **Prereq: Phase 2.**

**Master plan:** `.kilo/plans/1787912690309-master-plan.md` — read **§1, §2 (D5, A1, A2, A4, A6), §5 (events, threading, failure modes), §8.5, §9 (integration)** before starting.

## Goal
A production-quality `sshengine` + `sshx` that can connect any stored session (password or key, 0..N jump hosts, extra-arg forwards), stream a PTY to the (future) xterm.js via Wails events, and pass an integration suite against real sshd containers.

## Tasks
1. `internal/sshx/args` — the Extra Args parser (strict):
   - Tokenizer (shell-style: quotes, `-L 127.0.0.1:8080:db:5432`, `-o Key=Value`, `ProxyJump=user@host[:port]`).
   - Supported: `-L [bind:]local:dstHost:dstPort`, `-D [bind:]localPort`, `-o` only for `ServerAliveInterval`, `ServerAliveCountMax`, `ConnectTimeout`, `StrictHostKeyChecking` (no/ask), `ProxyJump` (maps into the jump chain, appended AFTER structured ones).
   - Output: `Parsed{Forwards []Forward, Options Options}` + normalized; reject unknown flags / malformed values with descriptive errors (`"unsupported flag -A"`, `"invalid local port in -L spec"`).
   - `Validate(spec string) error` exported for `SessionService.ValidateExtraArgs`.
   - Unit tests: full table (every supported form, every rejection, quoting edge cases, ProxyJump with port/user variants).
2. `internal/sshx` auth builders + host-key callback factory:
   - From `model.Auth` → `[]ssh.AuthMethod` (password; key via `ssh.ParsePrivateKey/ParseRawPrivateKey` + optional passphrase; key file read from absolute path, errors mapped to friendly strings).
   - `HostKeyCallback` backed by Phase 2 `knownhosts`: known-good → accept; mismatch → `ErrHostKeyChanged` (typed, includes expected/actual fingerprint); unknown → suspend on a per-conn promise resolved by `VaultService.ApproveHostKey/RejectHostKey` after `vault:hostkey-prompt` event.
3. `internal/sshengine`:
   - `SessionManager` (mutex + map tabID→`*liveConn`):
     - `Connect(session *model.Session, keyPassphrase string) -> (tabID, error)`: build chain — for each jump host then target: `net.DialTimeout` (10 s / ConnectTimeout) → `ssh.NewClientConn` (host-key cb) → `ssh.NewClient`; final hop keeps the client; intermediate clients stay open as long as the chain is live.
     - PTY: `RequestPty("xterm-256color", 24, 80, TerminalMode)`, `Shell()`, `Session.Stdout`/`Stdin`/`Stderr` pumps.
     - Output pump: batch buffer per tab — flush on 50 ms ticker OR ≥16 KB OR EOF (`terminal:data` b64, §2 A6); 1 MiB pending → pause reading (drain-resume on emit).
     - `Write(tabID, b64)`, `Resize(tabID, c, r)` (`Session.WindowChange`), `Disconnect(tabID)` (close channel+clients, forwards, emit `terminal:status closed`), `Reconnect(tabID)`.
     - Status events: `connecting` on start, `ready` after pty+shell, `error {message}` on any dial/auth/hostkey failure, `closed` on local close, `terminal:exit {exitStatus}` when remote shell exits (state→`closed`).
     - Local forwards from `args.Parsed.Forwards` (plus `ProxyJump`-implied chain already handled): `client.Listen("tcp", bind)` → `net` accept loop → `client.HandleConn`; emit `ssh:forward` (`listening`/`closed`/`failed`); on bind failure → warn, continue (master §5 failure modes).
     - Key with passphrase not provided → emit `vault:key-prompt {tabID, keyPath}`, suspend until `SubmitKeyPassphrase` or timeout 120 s → error.
     - Jump-host credential error attribution: error messages name the hop (`"jump host prod-jmp: auth failed"`).
   - Lifecycle: `Shutdown()` (called on `VaultService.Lock` and app exit) closes everything synchronously ≤ 3 s.
   - `TestConnection(dto)`: full dial incl. jumps + host-key handling, `client.Close()` immediately, return `ok` or error (used by Phase 4 editor).
4. Wire into `internal/wailsvc`: implement `TerminalService` (`Connect/Disconnect/Write/Resize/Reconnect`), replace the `ValidateExtraArgs` and `TestConnection` placeholders; pass `app.Event` emitter + a `PromptApprover` interface that `VaultService` satisfies (host-key / key-passphrase approvals resolve engine promises).
5. `docker/sshd` integration-image (openssh-server, users `alice`/`bob`, password + RSA/ED25519 key with passphrase, known authorized keys, one container used as target and as jump source) + `internal/sshengine/integration_test.go` (build tag `integration`, testcontainers-go):
   - password auth connect + PTY echo; key auth (no passphrase); key auth WITH passphrase (via manager prompt path, resolved programmatically); jump chain through a second container; `-L` forward dial-through; unknown host key → prompt → approve → connected, and again → cached in known_hosts; modified key → hard fail with `ErrHostKeyChanged`; bad port → `terminal:status error` with message; disconnect → events ordered (`status closed`); `Write` after close → typed error.
   - Fixture: 300 sessions loaded from Phase 2 fixture — `Connect` on 3 of them concurrently, then 10 sequential connects, measure (record, no hard assert beyond < 2 s per connect to localhost containers).

## Verification
- `make test` (race) green: args parser + known_hosts + auth builder unit tests.
- `make test-integration` green in a container with Docker socket (clean container, no host sshd).
- Manual spot check (optional, `make dev`): create a session in a temporary `go run` seed tool, connect in the placeholder window via a console-callable dev hook — NOT required; integration suite is the gate.
- `go vet` + `golangci-lint` (new linters enabled: `errcheck` strict for this package, `gosec` key-handling rules) clean.

## Exit criteria
Every event in the master §5 contract that this phase owns is emitted in the correct order (asserted by tests capturing events); parser rejects 100% of unsupported input with actionable messages; engine is leak-free (`Shutdown` closes all sockets/clients — verified by `SS`-free test: after shutdown, no goroutines holding conns, race-clean).
