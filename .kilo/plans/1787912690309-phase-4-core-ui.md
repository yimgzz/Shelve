# Phase 4 — Core UI: Unlock, Tree, Search, Tabs, Session Editor, Terminal, Settings

**Type:** Frontend (uses Phase 2/3 bindings; no backend changes expected — if a binding gap is found, fix backend in the same phase and re-test `make test`). **Prereq: Phase 3.**

**Master plan:** `.kilo/plans/1787912690309-master-plan.md` — read **§2 (A3–A9), §5 (full event contract), §6 (all — this phase implements it), §11 (Wails beta isolation)** before starting.

## Goal
The full desktop UI per master §6: unlock gate, left panel (search + tree + toolbar + gear), right pane (tabs + xterm.js terminal + status bar), session editor modal, settings modal, theme engine, toasts/confirms, shortcuts — all in vanilla TS on the Phase 1 Vite template.

## Tasks
1. **Theme engine + styles**: token sets for light/dark (master §6), base reset, layout CSS grid: `left panel | splitter | right pane`; splitter drag (pointer events, min/max 240/480, persist via `SessionService`? No — via `AppService.SaveSettings` window.leftWidth).
2. **main.ts bootstrap**: `AppService.GetSettings()` → theme → `VaultService.Status()` → render unlock gate or app shell; subscribe ALL master §5 events once at startup (single bus object; components subscribe to the store, not raw events); `vault:state-changed` → full UI swap (destroy all xterm instances, close nothing else backend already did).
3. **Unlock screen**: first-run (no vault) create-password flow (min 8, confirm match, strength hint via `zxcvbn`? NO — no extra dep: simple length/charset heuristic hint), unlock flow; Enter submits; wrong pw → inline error + shake; success → `AppService.GetSettings` + `SessionService.Tree()` render.
4. **Tree + search**: store `Tree()` DTO → DOM (folders: chevron + name + count badge (sessions+folders inside)); selection (blue), double-click session → `Tabs.open(session)`; context menus (New Session/New Folder/Connect/Edit/Duplicate/Move to…/Delete) using `components/context-menu.ts` (positioned, Esc closes, outside-click closes); F2 inline rename (input replaces label, Enter/blur commits, Esc cancels); Delete → `confirm` with counts (A8); Move to… → submenu of folders (excluding self/descendants). Search: on input debounce 100 ms → filter flattened nodes by name/host/user (case-insensitive substring; host/user only exist on sessions) → render Results list (name, host, folder path, highlighted `<mark>`); Esc clears; empty state text per §6.
5. **Tabs + terminal**: `Tabs.open` → `TerminalService.Connect(sessionID)` → creates tab (state connecting) immediately, `terminal:status` updates the dot; xterm instance created per tab (hidden until active); `terminal:data` → `term.write` (base64 decode — use `atob` + Uint8Array; keep a single decode helper); `xterm.onData` → `TerminalService.Write` b64 (throttle: coalesce per animation frame with requestAnimationFrame batching); ResizeObserver + `fit.addOnResize` → `TerminalService.Resize`; active-tab switch = show/hide panes (xterm survives, `fit()` on show); `terminal:exit` → overlay “Connection closed (exit N)”; `terminal:status error` → overlay card with message + [Retry]=`Reconnect` [Close tab]; status bar text per §6 (host, via jumps — jump names from session DTO, forward count from `ssh:forward` events cached per tab).
6. **Session editor modal**: all §6 fields; on open with draft (New/ Edit/Duplicate prefill); auth radio swaps sub-fields; key path uses a Browse… button → Go file dialog (add small `AppService.PickFile(kind "key")` in Phase 2 service set IF the Wails v3 dialog API is available at pinned version — else plain text input, note in README); jump repeater rows with add/remove; Extra Args: on blur → `SessionService.ValidateExtraArgs`, inline red text; `Test connection` → `SessionService.TestConnection(draft)` → toast result (works on unsaved draft); Save → Create/Update → store `Tree()` refresh → toast.
7. **Settings modal**: 3 groups per §6; theme radio triggers immediately; SFTP checkbox persists only (panel lands in Phase 5); terminal font/size/scrollback applied live; textEditorCommand free text (default `xdg-open`).
8. **Toast/confirm + shortcuts + empty states** per §6; `app:toast` event → toast list.
9. **Lock button** (gear menu: “Lock vault…”, Settings, About/version): confirm if any `ready` tabs → `VaultService.Lock()` → UI swaps to unlock screen.
10. **Auto-lock** (when `autoLockMinutes>0`): reset timer on any pointer/key event; fire → confirm-free `VaultService.Lock()` → same swap (per D3).
11. Cleanup: delete Phase 1 template leftovers; `frontend/index.html` gets `<html data-theme>` handled by theme.ts; title “Dummy SSH Manager”.
