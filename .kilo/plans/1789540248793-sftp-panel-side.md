# SFTP panel dock side (left / right)

## Goal

Let the user choose which side the SFTP browser is docked on. Default is
**left** when the browser is enabled. On the left it takes the place of the
session tree and a top-of-column toggle switches between the tree and the SFTP
panel. Right docking keeps today's behavior unchanged.

## Approved decisions

1. **Default side = left.** Persisted setting `sftpPanelSide: "left" | "right"`,
   default `"left"` (absent/unknown value → `"left"`).
2. **Tree stays the default left view.** No auto-switch on connect when docked
   left. The existing auto-open-on-ready-tab rule keeps applying only when
   docked right.
3. **Chosen in Settings** → General, a "SFTP panel position" dropdown directly
   under the "SFTP browser" checkbox. That is the only place the side changes.
4. **Toggle button placement:** one small icon button pinned in a fixed slim
   header row at the top of the left column, visible in both states. It shows a
   folder/SFTP glyph while the tree is visible (target = SFTP) and a list /
   sessions glyph while SFTP is visible (target = tree), with matching
   `title` + `aria-label` ("Show SFTP browser" / "Show sessions"). It is
   disabled (with a "Connect to a session…" tooltip) when no ready tab exists,
   so the row does not appear/disappear as tabs connect.
5. **Width:** left-docked panel reuses `window.leftWidth` (240–480) and the
   existing left splitter. One column, one persisted width; no new geometry.

## State model

- New persistent setting `sftpPanelSide` (`config.Settings`, `rpc/types.ts`).
- `sftpPanelOpen` stays ephemeral but its initial value becomes **`false`**
  (today `true`). Right-side observable behavior is unchanged because a ready
  tab auto-opens it; left-side default is then the tree.
- Gate both auto-open sites (`store.activateTab`, `store.setTabState`) with
  `settings.sftpPanelSide === "right"`.
- `sftpPanelVisible(state)` (store.ts:614) stays the base predicate
  (`enabled && open && ready tab`). The shell decides which column it drives.
- Toggle click = `store.set({ sftpPanelOpen: !sftpPanelOpen })`.
- Switching side in Settings while the panel is open keeps it open on the new
  side (explicit user action, not an auto-switch).

## Behavior spec

**Docked right (existing, unchanged):** tree always visible on the left; SFTP
in the right column; `×` closes, toolbar `[SFTP]` reopens; auto-opens on tab
ready.

**Docked left:** the left column shows exactly one view at a time.
- `sftpBrowserEnabled === false` → plain tree, no switcher row, no SFTP view.
- enabled + no ready tab → tree + existing "Connect to a session…" hint; toggle
  row visible but the button is disabled.
- enabled + ready tab + `sftpPanelOpen === false` → tree view.
- enabled + ready tab + `sftpPanelOpen === true` → SFTP view.
- The right SFTP column and its splitter are not created in left mode; the left
  splitter keeps resizing `--left-w` (240–480 clamp).
- Hide the panel-header `×` in left mode (`.sftp-close` under a
  `body.sftp-left` rule): the top toggle is the single control back to the tree.

**Mode change:** changing `settings.sftpPanelSide` re-renders the shell (see
task 5). The SFTP panel re-mounts and re-lists from the initial path;
terminals persist (`TermPool` + module `panes` map).

## Out of scope

- Drag-and-drop re-docking, a per-session dock side, per-session width.
- Keyboard shortcut for the view toggle (only Ctrl+Shift+E toggles the browser
  *enabled* setting today; leave as is).
- Independent width for the left-docked SFTP panel.

## Risks / notes

- `sftpPanelOpen` initial `false` is required for the left default; verify right
  mode still auto-opens on ready (it does via the gated auto-open).
- Changing the default from right to left is an intentional user-visible change
  (this request), so the master-plan "no functional change rule" does not apply.
- Re-rendering the shell on side change resets the SFTP browsing path to the
  initial path; acceptable for a deliberate settings action.
- `sftpPanelWidth` / its clamp stay in use only in right mode.

## Manual QA checklist

1. Fresh settings → SFTP enabled, side left; tree visible; toggle at top-left.
2. Connect a session: left stays on the tree (no auto-switch); toggle becomes
   enabled; clicking shows SFTP; clicking again returns to the tree.
3. No ready tab: toggle row present, button disabled with the connect tooltip.
4. Docked right: behavior identical to before (auto-open on ready, `×` closes,
   `[SFTP]` reopens, right splitter 200–640).
5. Switch side in Settings while the panel is open → panel appears on the new
   side; persisted across restart; settings.json contains `sftpPanelSide`.
6. Left splitter still clamps 240–480 and persists `window.leftWidth`.
7. Lock/unlock, theme switch, and narrow-window resize: no stray gap, terminal
   keeps working, toggle state consistent.
8. a11y: toggle has an action-describing `aria-label`; SFTP panel keeps
   `aria-label="SFTP browser"`.
