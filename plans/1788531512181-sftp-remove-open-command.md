# Plan — SFTP: remove the "Open" command; double-click file = "Edit as text"

> Status: Ready for implementation
> Date: 2026-09-04
> Scope: full removal of the SFTP "Open" feature (UI + backend + setting) and re-pointing file double-click to the "Edit as text" flow.

## 1. Goal

- The separate **"Open"** command for remote files (P002 `OpenRemoteFile` /
  `sftpOpenCommand`) is removed entirely — confirmed decision with the user
  (full removal, no dead code).
- **Double-click on a file** now executes the existing **"Edit as text"**
  logic (`EditRemoteText`): download to `tmp/`, open in the configured
  editor, save-detection re-upload.
- **Double-click on a directory** still navigates (unchanged).
- The context menu keeps **"Edit as text"** and the rest of its items; the
  "Open" item is deleted.

Resulting context menu for a file row: Edit as text / Download… / Upload to
here… / New folder… / Rename… / Delete… (for directories "Edit as text"
stays disabled, as today).

## 2. Master-plan references (read before implementation)

- [`plans/1787912690309-master-plan.md`](1787912690309-master-plan.md)
  - **§5 Architecture** — `SftpService` contract; bindings are generated by

  - **§8 Security** — tmp/ 0600 lifecycle, `settings.json` must stay

- [`plans/P002-sftp-browser-enhancements.md`](P002-sftp-browser-enhancements.md)

## 3. Behavior after the change

| Action | Before | After |
|---|---|---|
| Double-click dir | navigate | navigate (unchanged) |
| Double-click file | `OpenRemoteFile` (local default app) | `startEdit` → `EditRemoteText` |
| Context menu "Open" | present | **removed** |
| Context menu "Edit as text" | present | present (unchanged) |
| Settings → Files "Open command" | present | **removed** |
| Double-click a >2 MiB / binary file | opens in default app | error toast (`ErrTooLarge` / `ErrBinary`); user falls back to "Download…" |

## 6. Exit criteria

- No "Open" surface remains: no context-menu item, no double-click action,
  no settings field, no backend method, no config key (grep `OpenRemoteFile`
  / `sftpOpenCommand` should return only historical `plans/*.md` hits).
- File double-click behaves exactly like the "Edit as text" menu action.
- `make test` + `make lint` green in a clean container.

## 7. Risks / notes

- Stale on-disk bindings still type `OpenRemoteFile` until regeneration;
  `tsc` passes regardless (the call is gone), but regenerate during the
  validation build to keep bindings in sync.
- `ErrBinary` toast text is user-visible — covered by QA item 5.2.
- Out of scope: master-plan doc updates; any new "binary → download"
  fallback UX; changes to `Download…`/`DownloadThenSave`.
